# Accredit.vip — AI Agent Guide

## Project Overview

Accredit.vip is an event management platform (RSVP, ticketing, payments, wallet, invitations, QR accreditation) using:
- **Frontend:** Next.js 14 (App Router, TypeScript, Tailwind CSS) at `frontend/`
- **Backend:** FastAPI (Python 3.11+, SQLAlchemy async) at `backend/`
- **Database:** PostgreSQL
- **Server:** Namecheap VPS, Ubuntu 24.04, nginx reverse proxy

## Deployment Guide (STRICT)

### Preferred path: push to `main` (GitHub Actions, live since 2026-10-26)

`.github/workflows/deploy.yml` builds and deploys on every push to `main` of `Farfesadee/accredit.vip`, or on demand from the Actions tab. **Wait for the green run before telling anyone the change is live.**

What it does, in order: `npm ci` + `tsc --noEmit` + `npm run build` on the runner (Node 24) -> backend `python3 -m compileall` -> `rsync` source and the built `.next` to `/var/www/accredit.vip` -> on the VPS, `npm ci` and `pip install` **only when `package-lock.json` / `requirements.txt` changed** (stamped in `/var/www/accredit.vip/.deploy-lock-stamp`, `.deploy-req-stamp`) -> `systemctl restart accredit-api.service accredit-web.service` -> health-check loop on `127.0.0.1:8001/api/v1/health` and `127.0.0.1:3000/`, failing the job (with journal tails) if either never reaches 200.

Rules that keep it safe:
- **The server never builds.** The runner produces `.next`; the VPS only installs dependencies, restarts and verifies. This keeps `next build` off a 4-core box that is serving live tickets.
- **Source rsync has no `--delete`** so server-only files survive every deploy: `frontend/.env`, `public/a014r3xzq87gozz0k9fxemrc905wyw.html`, `public/googleaa4c2812fd852235.html`. Only `.next` is replaced wholesale (with `--delete`), so removed routes really disappear.
- **`frontend/package-lock.json` must stay in sync with `package.json`.** The 2026-10 patch replaced a lockfile that was missing every optional platform binary (npm refused `npm ci` everywhere with `EUSAGE`). If a lockfile edit is needed, regenerate it on Linux (`npm install --package-lock-only`), then prove `npm ci` succeeds before pushing.
- **Secrets live in the repo, not here:** `VPS_HOST`, `VPS_USERNAME`, `VPS_PORT`, `VPS_SSH_KEY` (the `github-actions-deploy` RSA key, public half in `/root/.ssh/authorized_keys`), `NEXT_PUBLIC_GOOGLE_CLIENT_ID`. `NEXT_PUBLIC_API_URL` and `NEXT_PUBLIC_SITE_URL` are set inline in the workflow because both are baked into the client bundle at build time.
- **Never `git pull` on the server.** `/var/www/accredit.vip` is a stale repo whose `origin` is an unrelated project; deploys are file transfers, always.
- **Local remotes:** `origin` is `https://github.com/Farfesadee/accredit.vip.git`, the repo the pipeline watches, and local `main` tracks `origin/main`, so a plain `git push` is correct. The old `nomba_2026_hackathon` remote is kept under the name `nomba`, and the pre-snapshot 330-commit history is preserved as the local branch `old-main-2026-08`. The `server` remote points at the VPS repo and is never used for deploys.
- `frontend/next_build.tar` (29 MB, stray) is excluded from the transfer.

The manual `scp` / zip procedures below still work and remain the fallback if Actions is unavailable.

## Guest Email Design Rule — STANDING (user directive 2026-10-20)

**Every guest-facing email from every dashboard, current and future, must be a designed HTML email built in the event's own palette. A plain or default-styled email is a defect, not a shortcut.**

## Event Montage Standard — STANDING (user directive 2026-10-22)

**Any event that opens with a montage must be built to this standard. There is no such thing as a "quick" montage, and a slideshow with default fonts is a defect.**

Three montages are live and approved. They are the template shelf: copy one and re-skin it, or build something new that still satisfies every rule below.

| Event | File | Shape | Length |
|---|---|---|---|
| 84 Nelkon & Blessing 30th anniversary | `/uploads/anniversary-montage.mp4` | 1080x1920 vertical | 15.0s |
| 82 The Art of Attention | `/uploads/gala-film.mp4` (desktop) + `/uploads/gala-film-vertical.mp4` (phone) | 1920x1080 and 1080x1920 | 31.8s |
| 80 Patrick & Sarah | `/uploads/wedding-invite-open.mp4` (client curtain clip, upscaled) | 1080x1974 vertical | 4.0s |

### 1. The montage is silent. Always.
- Encode with `-an`. The file carries **no audio stream at all**.
- The event's song belongs to **one** `<audio>` element mounted outside every conditional branch in the page component. It starts on arrival, keeps playing across cover, montage and invitation, and is never remounted, never restarted, never duplicated.
- A montage with its own soundtrack is the bug that made "Ordinary" restart at every stage on event 84. Never do it.
- The `<video>` element is always `muted` and `playsInline`.

#### Music default: SOUND ON - STANDING (user directive 2026-10-25)

**Every montage dashboard opens with its music already playing. Sound on is the default, and the guest is the only one who can stop it. No page may ever ask the guest to tap for sound.**

- The music starts **on the welcome screen**, while the spinner is still up: the page starts it as soon as the event payload arrives, before the invitation component mounts. It then runs continuously through the cover, the film and the invitation, for as long as the guest stays.
- **There is no "Tap to open", "Tap for sound" or "Tap anywhere for sound" anywhere**, and no text label on the Sound control. The prompt wording was wrong and was removed (user directive): a visible tap prompt means the sound design is broken. The control is an icon-only button at every stage (cover, film header, invitation header) with an `aria-label` of "Turn the music off" / "Turn the music on".
- **Full volume.** The one song plays at `volume = 1` (2026-10-25: raised from 0.62 on client request). A Web Audio gain stage could go louder but stays silent until a gesture, which defeats the point, so 1 is the ceiling.
- **One song, one element, one visit.** The song lives in `frontend/src/lib/invite-music.ts`, a module-level singleton that creates its own `<audio loop preload="auto">` with `document.createElement` (not part of the React tree). Pages call `inviteMusic.start(url)` during the welcome screen and `inviteMusic.stop()` on unmount; components call `useInviteMusic(url)` only to read state and get the toggle. Remounts, stage changes and route steps can never restart it. Never put the `<audio>` back inside a component branch.
- Nothing on the page pauses it. Not the cover parting, not the film ending, not a stage change, not a re-render, not a scroll, not a tap on a photograph, a form field or a button. Only the guest's Sound control stops it.
- Once a guest has turned it off, nothing may start it again: no timer, gesture, scroll, route change or remount. The control brings it back, and it **resumes** where it was rather than restarting from zero.
- **Browsers legally refuse audible autoplay until the visitor interacts with the page.** That is a platform rule, not a defect, and it cannot be bypassed. Handle it the approved way: attempt an inaudible `play()` (volume 0) and raise the volume to 1 immediately, retry on `loadedmetadata / loadeddata / canplay` and every 250ms for a few seconds (a first attempt can be refused while the document is still settling), and when the sound is still held back keep the same track **running silently and in time**, then unmute inside the first real gesture of any kind (`pointerdown / pointerup / touchstart / touchend / click / keydown / wheel`), calling `play()` inside the gesture because iOS requires it. Never start playback from a `setTimeout` after a tap: that breaks the gesture chain.
- Never show a chip, banner or hint about sound. The icon changes to a muted speaker while the browser is holding it back, and that is the whole message.
- When a client film carries its own score, extract it as its own file, strip the film's audio stream (`-c:v copy -an`), bump the `?v=`, and let the singleton own the sound so it keeps playing after the film ends (event 82, `/uploads/gala-score.mp3`).
- The anniversary (event 84) and gala (event 82) pages are the reference implementations.

### 2. Two cuts, never one stretched
- **Phone: 1080x1920 (9:16).** Serve it with `matchMedia("(max-width: 767px)")` and swap the source. A 16:9 film shown on a handset is a stamp in the middle of the screen, not an opening.
- **Desktop: 1920x1080 (16:9).** Only when the client's artwork supports a wide scene. If it does not, a single vertical cut used full-bleed on desktop is acceptable (event 84), but never letterbox a wide film into a portrait frame.
- Every cut must be legible at 360px wide. If a line of type cannot be read on a 375px phone, it is too small.

### 3. Length and pacing
- **Opening montage: 12 to 20 seconds.** It gates the invitation, so it must feel like a title sequence, not a film. Event 84 runs 15.0s.
- **Long-form invitation film: up to about 35 seconds**, and only when the client supplied a score for it (event 82, 31.8s).
- **One move per 2.5 seconds minimum.** No beat shorter than 1.5s except a deliberate title flash.
- The film must end on its own and hand over to the invitation automatically. There is no "skip" button. The guest never has to tap twice.

### 4. The five beats
1. **Title card** built from the event's own lettering, on the deepest colour in its palette: the names, and the anniversary or date line. This is the first frame a guest sees while the flier cover parts.
2. **Portrait beats.** One photograph per beat, taken from the client's own artwork. Faces are always fully in frame, never cropped at the forehead or chin.
3. **Detail beat** (optional): hands, the dress, the venue, the invitation card, a ring, a cake. One only.
4. **Motion beat:** a slow drift on a still, or a soft clip of the client's own footage.
5. **Flier handoff:** close on the client's flyer or hero artwork, so the cut into the invitation reads as a continuation rather than a jump.

No stock photographs. No AI-generated people. No text baked into frames that repeats the page copy word for word.

### 5. Typography
- Take the faces from the client's own artwork (the PDF or flier), or the closest freely hostable match. Event 84 uses Urbanist (the exact PDF face) with Yellowtail and Great Vibes standing in for the two script faces.
- Display type on a vertical cut: about 130px at 1080 wide. Eyebrow labels: 30 to 34px, uppercase, tracking 0.3em or wider.
- Never ship a montage in a default system font. That is what "less creative" means.

### 6. Motion and transitions
- Crossfade 500 to 800ms, or a slow Ken Burns push (scale 1.00 to 1.06 over the beat).
- **No hard cuts, no whip pans, no zoom punches, no spinning, no flashing.** Nothing that reads as a template transition.
- All text sits still. If the frame moves, the type does not move with it.
- Total moving elements per beat: one.

### 7. Colour
- Palette comes from the event's own flyer and `theme_color`. Event 84 is aubergine and lavender, event 82 is black and gold, event 80 is cream and gold.
- Never brand pink `#E91E8C`, never another event's palette, never the platform teal unless the event has no artwork at all.

### 8. Repairing a client clip that contains stale copy
When the client's own footage carries an outdated title, date or venue baked into the pixels, do not re-edit the whole film. Overlay an opaque, typographically matched card on the offending window (`drawtext` or a PNG card), keep the client's score untouched, and re-encode only the video stream (`-c:v ... -c:a copy`).
- Drive the card inputs with finite durations (`-loop 1 -framerate 30 -t <len>`). Unbounded image inputs make the filter graph loop forever.
- **Check the seams:** extract frames at each boundary minus and plus 0.1s and confirm no old copy leaks and no half-faded card appears.

### 9. Encoding and hosting
- H.264, `yuv420p`, 30fps, `-movflags +faststart`.
- Budget: **4MB for a vertical opening montage, 6MB for a desktop cut.** If it is bigger, the guest is watching a download.
- No audio stream (`-an`). Strip metadata.
- Host at `/var/www/accredit.vip/backend/uploads/<event>-montage.mp4`, owner `deploy:deploy`, mode 644, with a poster JPG extracted from frame 0 next to it.
- Bump the URL (`?v=2`) in the content payload whenever the file changes, otherwise guests keep the cached old cut.
- Keep the previous file as `<name>-v1.mp4` for rollback instead of overwriting it blindly.

### 10. Playback contract in the page
- `<video muted playsInline preload="auto" poster={...}>`, always.
- Start it on the gesture or timer that opens the page, and again on the mount effect plus `onLoadedData` and `onCanPlay`. Never start it from a `setTimeout` after a tap: on phones that breaks the gesture chain and the film freezes on the poster until a second tap.
- `onEnded` **and** `onError` both advance to the invitation. A broken film must never trap a guest.
- Stall guard: if the element is still paused about 2 seconds after opening, show a small "Tap to play" fallback (a real control) and keep the invitation reachable.
- Do not set `poster` while an opening cover is on screen. The cover already shows the flier and the poster draws it a second time underneath.
- Buffering state: show a small indicator, not a frozen frame.

### 11. Accessibility
- The film is decorative: `aria-hidden` on the video, no caption track required, no autoplaying sound.
- Respect `prefers-reduced-motion`: skip the montage and land on the invitation.
- No flashing content, no strobe, nothing above three flashes per second.

### 12. Definition of done (run all of it before telling the client)
1. `ffprobe` shows the right resolution, duration, and **zero audio streams**.
2. Frames extracted at five points (first, two middles, last, and each card seam) are inspected.
3. Both cuts loaded in a real browser at phone and desktop widths, with the correct one served on each.
4. One tap (or none, for auto-open covers) reaches the invitation, and the song plays continuously straight through the montage into the page.
5. File size within budget, `?v=` bumped, old file kept for rollback.
6. The page still passes the standing checks: no em dashes, no emojis, no `#E91E8C`, no horizontal overflow at 360/375/393/420/1400, burial and pickup files untouched.
